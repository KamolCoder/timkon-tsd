# ТСД: проверка перемещений (FlutterFlow Custom Code)

Кладовщик открывает непроведённое перемещение «Склад → Магазин» и сканирует собранный товар.
Приложение показывает недостачи, лишнее и пересорт, затем записывает фактические количества
в 1С (OData, по LAN). Проводит документ кладовщик в 1С.

## Как работает (офлайн)

1. **Начало смены, Wi-Fi есть:** на списке кнопка **«Загрузить»** скачивает на ТСД все непроведённые
   перемещения склада за N дней со строками + названия, единицы и штрихкоды товаров.
2. **Проверка — без сети.** Документ открывается с ТСД, сканирование и сверка полностью локальные.
   «Готово» сохраняет результат на ТСД (статус «проверен, ждёт отправки»).
3. **Отправка:** сразу после «Готово», если есть связь; иначе кнопка **«Отправить (N)»** на списке.
   Перед записью документ перечитывается: если в 1С его изменили, провели или удалили после загрузки,
   он не перезаписывается — статус «конфликт» (тап → «Удалить с ТСД», затем «Загрузить»).

Повторная «Загрузить»: добавляет новые документы, обновляет нетронутые, убирает проведённые/удалённые;
документы в работе не трогает (если их изменили в 1С — «конфликт»).

Статусы в списке: новый (белый) · в работе (жёлтый) · проверен, ждёт отправки (зелёный) · конфликт (красный).
Отправленные переходят на вкладку **«Отправленные»** (хранятся на ТСД 7 дней: номер, магазин, время, журнал проверки;
tap — подробности и «Убрать из истории»). Данные хранятся в SharedPreferences ТСД (`tsd_docs`, `tsd_doc_*`, `tsd_prod_*`);
товары, которых нет в загруженных документах, удаляются при загрузке.

## Страницы

На каждой странице только один виджет на весь экран (width/height = ∞ или в Expanded).

### 1. Settings
- `TsdSettingsWidget`, параметров нет.
- Адрес 1С (`http://IP/tbase`), пользователь, пароль, кладовщик, за сколько дней;
  «Проверить связь и загрузить склады» → выбрать склад.

### 2. TransferList (Initial Page)
- `TransferListWidget`.
- `onOpen` — Action **с параметром `transferKey` (String)** → Navigate To **TransferCheck** с `transferKey`.
- `onSettings` — Action → Navigate To **Settings**.

### 3. TransferCheck
- Page Parameter `transferKey` (String) → в `TransferCheckWidget.transferKey`. Больше ничего.
- Скан → окно «Количество» (предзаполнено: 1, для штрихкода упаковки — её количество из 1С), Enter — добавить.
  Скан следующего товара прямо в окне: текущий добавится с предзаполненным количеством, окно откроется для нового.
  Товар не из документа — окно красное с пометкой «НЕТ В ДОКУМЕНТЕ».
- Вверху поле «Сканируйте штрихкод…» — фокус на нём всегда (возвращается после каждого окна), экранная
  клавиатура не открывается; ⌨ в поле — включить клавиатуру для ручного ввода. Скан принимается по Enter,
  а если сканер не шлёт Enter — через 0,3 с после последнего символа (код ≥ 6 символов).
- Кнопки в шапке: режим скана (окно количества / сразу +1), ⟲ сбросить проверку.
- **«Готово» срабатывает только при удержании 1,5 с** (кнопка заполняется), короткое нажатие — подсказка.

## Один раз в проекте

**Android, HTTP без TLS.** 1С опубликована по `http://`, Android 9+ такое блокирует:
Custom Code → Configuration Files → `AndroidManifest.xml` → в `<application>` добавить
`android:usesCleartextTraffic="true"`.

**Сканер ТСД:** вывод «в поле ввода / эмуляция клавиатуры» (keyboard wedge), суффикс **Enter** (желательно).
Режим «Broadcast / Intent» не поддерживается. Без сканера — ⌨ в поле скана.

## Нагрузка на 1С (сделать один раз на сервере)

**Пул сеансов.** Без него каждый запрос открывает новый сеанс 1С (0,5–2 с на сервере и лицензия на время запроса).
В `default.vrd` публикации (каталог публикации на IIS/Apache) внутри `<point …>`:

```xml
<standardOdata enable="true" reuseSessions="autouse" sessionMaxAge="20" poolSize="5" poolTimeout="5"/>
```

Перезапустить IIS/Apache. Если такая строка уже есть, добавить в неё атрибуты.
Если веб-сервер после этого не стартует, платформа не поддерживает атрибуты: вернуть `<standardOdata enable="true"/>`.

**Сжатие gzip** (JSON сжимается в 5–10 раз, приложение само шлёт `Accept-Encoding: gzip`):
- IIS: роль «Dynamic Content Compression», в `applicationHost.config` → `dynamicTypes` добавить `application/json` и `application/json;odata=*` (enabled="true");
- Apache: `AddOutputFilterByType DEFLATE application/json`.

**Что грузит приложение:**
| Действие | Запросы |
|---|---|
| «Загрузить» | 1 (документы со строками) + товары пачками (≤ 1900 символов запроса; только новые или старше 12 ч) + раз в сутки склады |
| Проверка | 0 |
| Отправка документа | 1 GET + 1 PATCH |

## Логика проверки

- Штрихкод упаковки (единица 1С с `Коэффициент > 1`) предзаполняет её количество.
- Факт = план → 🟢, меньше → 🟡 недостача, больше → 🔴 излишек.
- Штрихкод не из документа → строка «нет в документе» (название — если товар есть в других загруженных
  документах), неизвестный штрихкод → «Неизвестный штрихкод …». Такие строки блокируют «Готово».
- Излишек и недостача → подтверждение; в 1С уходит факт, в комментарий —
  «излишек: товар план→факт» / «недостача: …». Товар не из документа → «Готово» запрещено (убрать или 0).
- Тап по строке → ввести факт вручную (весовой товар, крупные партии).
- Прогресс хранится на ТСД (переживает перезапуск) и удаляется после отправки.
- Отправка: перечитывает документ; если он проведён или изменён в 1С после загрузки, ничего не пишет.
  Иначе `Товары` = факт (строки с 0 удаляются, ссылка на заказ и цена сохраняются),
  в `Комментарий` дописывается «Проверено ТСД: …; излишек: …; недостача: …».

## Права пользователя 1С для ТСД

Чтение: номенклатура, единицы измерения, штрихкоды, склады, перемещения.
Изменение: перемещения. Добавление: единицы измерения.

Пароль 1С хранится на ТСД в настройках приложения: заведите для ТСД отдельного пользователя только с этими правами.
